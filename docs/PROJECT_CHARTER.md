## 一 依据与适用范围

- 《校园任务岛.docx》描述产品总体方向和后续目标。
- 根目录 README 描述当前版本功能与明确边界；分主题业务文档中的后续更新说明补充具体规则。旧阶段的实现记录和历史测试数量不代表当前版本。
- 文档互相冲突时记录为待确认的契约差异，不直接把现有实现视为正确标准，也不自行扩展产品范围。
- 本轮审查对象仅为 `E:\agent1`。旧 mini-openclaw 是提取来源，不是本项目的运行实现。部署到其他目录或电脑时，不应依赖这一审查路径。

## 二 当前版本的产品边界

| 板块 | 本版职责 | 明确边界 |
|---|---|---|
| 普通任务 | 发布、直接接取或申请后确认、阶段、成果、验收、双方变更、暂停恢复取消、线下结算声明 | 一项任务一位接取者；不处理线上支付 |
| 综素活动 | 定时开放、限额、审核、候补递补、个人记录与负责人名单 | 报名成功不等于学校认定；未接入正式认定系统 |
| 志愿服务 | 分岗位报名、参与登记、分钟数核验与个人记录 | 活动方确认与学校正式认定分开；没有线上签到签退 |
| 校园发现 | 图文发布、分类、评论、正文版本、状态更新和撤回 | 状态为发布者自报，不代表工作人员或学校确认 |
| 首页与消息 | 当前待办、等待事项、完成统计、站内消息及已读状态 | 消息已读不等于业务完成；没有定时或站外推送 |
| 引航员 | 活动规划、偏好草稿与持续匹配、业务查询、普通任务草稿与阶段建议、可视化调用轨迹 | 草稿经用户确认后发布；偏好经本人授权保存；报名审核仍在业务页面；发现只读，不生成官方认定 |
| 账号 | 注册、登录、退出登录、账号资料与主机端账号维护 | 退出仅撤销当前会话，账号与业务记录保留，可再次登录；普通用户无删除功能；仅主机管理员可本地删除无业务记录的非内置测试账号 |

多人协作、组织身份核验、官方链接报名、收藏提醒、丰富成长系统等策划案目标，不能仅因本版未实现就计为代码缺陷。新增需求仍须单独确认。

## 三 审查所依据的工程约束

1. 用户身份来自服务端会话。用户或模型参数不能伪造操作者；个人报名、协作材料、草稿、对话和运行记录按权限读取。
2. 四类业务独立。普通任务工具不代替活动报名、志愿小时或校园发现操作。
3. 写操作重新检查权限、当前状态、版本、截止时间和名额；需要共同提交的业务、历史、消息处于同一事务中。
4. 阶段按顺序执行，负责人提交、对方验收。变更在所需用户确认前不生效，历史内容不能被新版本覆盖。
5. 金额按整数分存储，用户界面明确展示单位；志愿记录按整数分钟存储，展示换算不改变业务原值。
6. 时间以服务端为准，输入须带时区，网页按北京时间展示。GET 不通过副作用批量改写业务状态。
7. 需要本人行动与等待他人分开展示；任务完成状态与结算状态分别处理。未完成任务、报名、核验或结算不阻止退出登录，退出不会终止这些业务。
8. 引航员只使用本次注册的工具，工具返回数据不作为系统指令。失败、超时或取消不提交本轮暂存草稿、建议和对话；终态与实际提交结果一致。
9. 文件和 shell 工具仅用于显式启用的通用 CLI 场景，目录由宿主绑定；shell 本身不提供操作系统级沙箱。
10. 当前运行方式为单进程、单实例本地或可信局域网原型。多 worker、多副本、公网部署不属于本轮已实现范围。

## 四 发现问题的记录方式

- **已确认 bug**：在本版范围内违背既定行为，并有源码调用链、可控输入或独立复现证据。
- **范围差异**：总体策划目标与当前版本能力不同，单列说明。
- **待验证疑点**：尚无充分复现证据，不列为已确认 bug。
- 原回归通过、静态构建通过和真实模型任务成功分别记录；不以其中一项替代其他项。

2026-10-16 需求澄清：“注销”仅指退出登录，普通用户没有永久删除或停用账号功能；历史数据库字段保留兼容，不自动恢复旧版本已停用账号。同日补充主机管理员维护需求：通过具有 Windows 提升权限或 Linux root 权限的本地终端列出、检查账号，并在明确确认账号 ID、备份和重新检查关联数据后，删除无业务及历史记录的非内置账号；网页登录用户没有对应接口或权限。已有业务、报名、消息、引航员记录、上传图片等关联数据的账号拒绝删除；内置三个演示账号由启动流程补建，本次保持保护。具体操作见 [主机管理员账号维护](ACCOUNT_ADMIN.md)。
