# 岛屿首页与站内消息

## 入口与使用

默认首页 `/#/home` 展示静态悬浮岛、四类列表入口和统一发布入口。品牌图标返回首页。旧列表、详情和登录返回链接保持可用。

登录后首页展示未读消息、本人参与且已完成的任务数，以及最多5条当前待办。协作数按任务去重，不累计徽章、经验或正式认定。验收／参与核验优先，其次申请审核，最后其他任务操作。

普通任务复用个人待办规则；综素待审核申请按活动合并；志愿审核、参与登记和小时核验按岗位与操作合并。候补、等待审核及校园发现自报状态不会自动变成操作义务。志愿岗位开始后才登记参与，结束或中途取消后可核验已发生的服务。已读消息不会消除业务待办。

左侧“消息”显示本人未读数量（超过99为99+）。消息页支持全部／未读、游标分页、点击已读并进入详情、全部已读。全部已读只处理本次查询的最大消息ID及之前消息，保留并发新消息。失败保留原数据与未读状态，提供重试。页面可见时每15秒刷新，业务操作成功后主动刷新；切换账号清空缓存。

## 通知覆盖

- 普通任务：新申请、申请通过／选择他人／任务下架、成果待验收、通过／退回。
- 阶段协作：安排更新、阶段开始、成果提交和验收；最后阶段通过与任务完成合并通知。
- 综素与志愿：提交待审核、报名成功、候补、审核结果、候补转正、活动方取消；负责人收到待审核及参与者取消。本人取消不额外生成自己的消息。
- 志愿记录：参与新增／更正、活动方小时确认／更正；更正参与导致旧确认失效时明确提醒重新核验。
- 校园发现：别人发表评论通知发布者，自己的评论不通知自己。消息不保存发现标题、评论正文或图片，撤回后仍无法从消息读取旧内容。

消息表示已经发生的变化，点击详情查看当前真实结果。参与说明、申请说明、成果正文及核验说明不复制到消息。小时确认统一标为活动方确认，学校正式认定尚未对接。

只记录上线后的新变化，不补发旧消息；历史未处理事项仍出现在首页。未获名额等时间计算结果继续在原业务页面显示，不定时生成消息。没有邮件、系统推送、定时提醒、私聊、消息删除或通知偏好。

## 工程接口

| 方法与路径 | 返回／操作 |
| --- | --- |
| GET /api/me/home | todos前5条、todo_count、completed_count、unread_count、server_time、next_boundary |
| GET /api/me/messages | unread_only、limit（1–50）、before_id；返回items、next_cursor、max_id、unread_count |
| GET /api/me/messages/unread-count | unread_count及服务端时间 |
| POST /api/me/messages/{id}/read | 本人消息幂等已读，其他用户消息返回404 |
| POST /api/me/messages/read-all | JSON {"through_id":123}，仅处理不大于该ID的本人消息 |

所有接口要求会话。消息由服务层在原业务事务内写入，消息失败则业务一起回滚。数据库新增notifications表（schema9），接收者＋事件键唯一，重复调用不新增；更正版本及新的申请／提交有不同事件键。所有GET接口保持只读，不补消息或标记已读。

首页摘要在同一只读快照中复用任务规则与志愿服务资格判断。引航员只指引首页和消息入口，不新增AI消息读取或标记工具。

## 验收

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
npm.cmd --prefix web run build
.\.venv\Scripts\python.exe -X utf8 -m examples.home_demo --port 8001
```

网页演示使用临时数据库、独立媒体目录和可推进的测试时钟。信息写入.runtime/home-demo.json；使用localhost:8001隔离正式127.0.0.1的Cookie。测试图片和输入为合成内容，不写入正式业务库。
