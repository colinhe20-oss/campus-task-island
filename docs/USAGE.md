# 校园任务岛界面使用说明

这份说明面向普通网页使用者，介绍当前版本各页面的入口和主要操作。项目结构与请求流程见根目录 [README.md](../README.md)。

## 1. 打开页面与登录

如果应用尚未启动，在项目根目录的 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn campus.app:app --host 127.0.0.1 --port 8000
```

没有账号时，在登录页选择“注册普通账号”，填写账号名、昵称和密码。账号名会忽略首尾空格并转为小写，需为 3–32 位字母、数字、点、下划线或连字符；注册密码长度为 6–128 个字符。可点击“显示密码”检查密码和确认密码后再提交。注册后会自动登录。新账号可以参与普通任务、报名活动和志愿岗位、发布校园发现，但不会拥有综素活动或志愿服务发布权限。

当前没有网页密码找回功能。忘记密码时，需要联系服务主机管理员在运行应用的主机上重置；管理员在项目目录执行：

```powershell
.\.venv\Scripts\python.exe -m campus.accounts reset-password <账号名>
```

命令会交互式要求输入两次新密码，不会把明文密码打印出来。重置后该账号的旧会话会失效。若服务使用了自定义 `CAMPUS_DB_PATH`，执行命令前也要在主机环境中设置同一个数据库路径。

登录后可从左侧个人账号卡进入“账号与隐私”。页面会列出阻止注销的未完成任务、申请、报名、负责人活动或志愿核验事项及对应入口；先完成或取消这些业务，再输入当前密码并勾选不可恢复确认。服务端会在注销时再次检查，避免检查列表后新出现业务导致历史被遗弃。

注销后账号不能登录或恢复，账号名也不能重新注册。任务、活动、发现、评论和志愿服务等业务历史会保留，账号展示名统一为“已注销用户”；引航员私人对话、未发布草稿、运行内容和个人消息会清除。注销不会替用户取消任务、报名或已发布内容。

然后打开 <http://127.0.0.1:8000/>。如果浏览器已能访问页面，或终端提示 8000 端口已占用，通常表示服务已经在运行，不要再启动第二份。

用户可通过登录页公开注册普通账号。首次启动时系统还会生成本机演示账号，凭据只保存在主机的 `.runtime` 目录；不要把该目录、用户数据库或 `.env` 密钥上传或发给他人。未登录也可以浏览公开列表和详情；发布、报名、协作操作、个人空间及引航员需要登录。登录后一般会返回刚才打开的页面。

## 双电脑局域网验收

一台电脑作为主机运行唯一的后端服务，另一台电脑通过同一个校园网络访问。两台电脑使用同一服务端数据库和图片目录，不要在第二台电脑再启动一份后端。

### 主机电脑

1. 确认主机和第二台电脑连在允许设备互访的同一个 Wi-Fi 或局域网；访客 Wi-Fi 可能会隔离设备。
2. 在项目根目录打开 PowerShell，运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start_lan.ps1
   ```

3. 记下脚本显示的局域网地址，例如 `http://192.168.1.23:8000/`。地址以本机实际输出为准，DHCP 地址可能变化。
4. 在主机浏览器打开该局域网地址，确认首页能正常显示；也可访问同一地址下的 `/api/health`，预期返回 `{"status":"ok"}`。
5. 保持启动窗口打开。验收结束后在窗口按 `Ctrl+C` 停止服务。

### Windows 防火墙

如果主机本机能打开页面、第二台电脑无法连接，先确认 Windows 网络配置为可信的专用网络，并查看是否出现“允许 Python 通信”的防火墙提示。仅在可信网络中允许专用网络访问。

需要显式添加规则时，以管理员身份打开 PowerShell，并只允许专用网络访问 TCP 8000：

```powershell
New-NetFirewallRule -DisplayName "校园任务岛局域网验收" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private
```

验收结束后删除该规则：

```powershell
Remove-NetFirewallRule -DisplayName "校园任务岛局域网验收"
```

不要为了验收把不可信校园网络改成专用网络，也不要为所有网络配置开放端口。若学校网络隔离设备或防火墙策略由学校管理，请遵守其规定，改用获准的私人网络。

### 第二台电脑与双人检查

1. 在第二台电脑浏览器输入主机 PowerShell 显示的完整局域网地址，确认首页、普通任务列表、活动、志愿服务和校园发现均能打开。
2. 用第一组演示账号登录并发布一条标题含“局域网验收”的临时内容。回到主机电脑，用另一组账号刷新列表，确认数据来自同一服务。不要把演示账号密码写入报告或截图。
3. 用两个不同账号分别检查权限：个人申请、我的空间、消息和引航员数据应按各自账号隔离；公开内容则可被另一台电脑浏览。
4. 双方分别进行一项无破坏性的操作，例如对发现内容发表评论，或对活动查看报名窗口；再检查消息／详情是否在另一台电脑刷新后反映相同服务端状态。
5. 验收结束后撤回或取消临时内容（按对应功能规则处理），退出账号并停止主机服务。

### 连不上时

- 确认第二台电脑使用的是脚本显示的地址，而不是 `127.0.0.1`；后者只指向访问者自己的电脑。
- 主机运行 `ipconfig` 确认无线网卡 IPv4 地址没有变化，并确认该地址与脚本显示相符。
- 在第二台电脑执行 `Test-NetConnection 主机IP -Port 8000`。若 `TcpTestSucceeded` 为 `False`，通常是防火墙、Wi-Fi 设备隔离或网络路由阻止了连接。
- 若网页可打开但登录失败，确认地址、端口和协议完全一致；登录 Cookie 绑定浏览器来源。不要一台电脑用 `localhost`、另一台用局域网 IP 来交替测试同一个浏览器会话。
- 若 8000 端口已占用，先确认是否已有校园任务岛服务运行；不要再启动第二个实例。

该方式用于可信局域网内的演示与测试。服务仍运行在主机上，主机休眠或关机后其他电脑无法访问；它不提供公网域名、HTTPS、自动备份或生产级部署保障。

## 2. 左侧导航

| 入口 | 用途 |
|---|---|
| 岛屿首页 | 查看四类内容入口、个人待办、未读消息和已完成协作数 |
| 普通任务 | 搜索和筛选普通任务，打开任务详情 |
| 综素活动 | 浏览活动、认定说明、报名窗口和名额 |
| 志愿服务 | 浏览志愿活动及其岗位、服务时段和报名情况 |
| 校园发现 | 查看设施、安全通行、趣味发现和校园生活分享 |
| 消息 | 查看业务变化通知，单条标记已读或全部已读 |
| 发布任务 | 先选择普通任务、综素活动、志愿服务或校园发现，再进入对应表单 |
| 我的空间 | 查看本人任务、申请、活动报名、志愿记录、发布的活动及发现 |
| 引航员 | 查询本人业务状态、跨板块待办，或整理普通任务发布草稿 |

首页仍以普通任务列表为默认业务列表；“发布任务”是四类内容共用的发布入口，不代表发布后都会生成普通任务。

## 3. 发布内容

点击左侧“发布任务”，选择内容类型后填写表单。提交失败时页面会显示原因并保留输入；发布成功会跳转到新内容详情。直接详情链接支持刷新和重新打开。

### 普通任务

填写标题、分类、需求说明、完成标准、地点和未来截止时间。选择无偿互助或有偿任务：有偿任务还需填写人民币金额和回报说明。接取方式可选“直接接取”或“申请后确认”，并可分别设置申请理由、技能经验和补充说明为关闭、选填或必填。发布后接取方式、申请字段规则和回报约定不能直接修改。

需要招募时可先浏览普通任务大厅。详情页会显示任务要求、截止、回报与接取方式：

- **直接接取**：按要求填写信息，勾选已阅读并确认任务条件后接取；多人争抢时服务端只允许一人成功。
- **申请后确认**：提交申请后等待发布者选择。等待确认不代表已经接取。
- 接取后双方可按详情中的阶段和提交要求协作。成果由对方验收；通过后才进入已完成。
- 约定变更、暂停、恢复和取消需要对方确认。提案确认前旧约定继续有效。提交中的成果须按页面提示先处理验收状态。
- 任务截止后未接取的任务停止新申请，发布者可延长；协作中的任务会显示逾期，但仍可按现有流程提交和验收。
- 有偿任务完成后，发布者与接取者分别确认线下付款／收款。平台记录双方确认，不发起或验证真实支付。

取消任务是独立终态，不会计为已完成。发布者可以把已取消任务的基本内容复制到新建表单，再重新检查截止时间和其他信息。

大厅支持按关键词、分类筛选，并可选择查看已截止但未接取的任务。已下架、已完成或已取消任务可能从默认大厅隐藏，但相关参与者仍可从个人记录或旧详情链接查看历史。

### 综素活动

负责人通过同一发布入口选择“综素活动”，填写活动说明、地点、活动时间、报名窗口、名额、报名方式和认定说明。活动负责人权限由服务端控制。

开放后按页面按钮报名或提交审核申请；满额时可能进入候补。负责人在活动详情管理申请，名额释放时系统按队列规则递补。活动详情和“我的报名”会显示当前结果及历史申请。活动组织方填写的认定说明不是学校正式认定，报名成功也不会自动增加学分。

### 志愿服务

发布时至少设置一个岗位，并填写岗位内容、要求、地点、服务时间、名额和预计小时说明。参与者选择具体岗位报名；名额、审核和候补按岗位分别处理。

活动开始时具备名额的参与者，负责人可登记参与情况与实际服务分钟数；活动后负责人再确认计入的小时。预计小时不自动成为实际小时，活动方确认也不等于学校正式认定。本人可在“我的志愿记录”查看当前结果和更正历史。

### 校园发现

所有登录用户都可以发布四类校园发现。填写标题、说明、地点、发现时间和信息来源，可上传最多三张图片。发现时间必须是当前之前的时间；图片上传后还需提交整条内容才会发布。

其他登录用户可以评论文字并附图补充情况。只有发布者可以编辑正文、更新状态或撤回内容；每次状态更新都要说明原因。页面中的“已核实”“处理中”等是发布者自报，不代表学校或工作人员已确认。撤回后公共页面不再展示原内容。

## 4. 我的空间、首页待办与消息

“我的空间”按类型查看本人发布、接取、申请和参与记录。普通任务申请撤回、活动／志愿报名取消、志愿记录和校园发现历史等操作以对应页面当前状态为准。

首页的“当前待办”只列需要本人操作的事项，例如成果验收、报名审核或志愿小时核验；候补或等待他人处理会显示为等待状态，不算作本人待办。首页只展示最多五条待办，完整入口会链接到对应业务页面。消息已读不会完成业务待办。

“消息”页按时间查看系统记录的业务变化。点击消息可标记已读并打开关联页面；也可单条已读或全部已读。消息说明事情发生过，具体结果以打开页面时的当前状态为准。页面在前台时会定期刷新未读数和消息。

## 5. 使用引航员

登录后打开“引航员”，可以直接询问例如：

- “我现在有哪些需要处理的事情？”
- “这个志愿岗位还有名额吗？”
- “我为什么还在候补？”
- “我的志愿小时为什么没有计入汇总？”
- “这个设施问题是发布者自报，还是工作人员确认？”

引航员使用只读工具查询四类内容和本人记录。涉及名额、候补或报名窗口时，回答基于工具给出的查询时间；提交报名时服务端会重新检查时间与剩余名额。志愿小时回答会区分活动方确认与尚未对接的学校正式认定。

引航员也可以根据对话整理普通任务草稿、补问地点／时间、接取方式、申请要求和回报约定。草稿需要在网页确认卡片检查后再发布；模型回复或出现草稿本身不会创建任务。阶段建议同样需要发布者确认。引航员不能替用户报名活动、登记志愿小时、评论或更新校园发现。

运行记录可查看引航员执行状态和工具反馈；支持的运行可以查看流式进度或请求取消。取消是对尚未完成的引航员运行发出请求，不会撤销已经完成的业务操作。

## 6. 常见提示

| 页面提示 | 处理方式 |
|---|---|
| 正在加载 | 等待请求完成；详情会从服务端读取当前结果 |
| 暂时无法加载／请求失败 | 使用页面“重新加载”或“重试”，已有表单输入通常会保留 |
| 需要登录 | 登录后返回原页面，再重新执行操作 |
| 没有权限 | 确认当前账号是活动负责人、任务协作方或内容发布者 |
| 任务或申请状态已变化／版本冲突 | 重新读取页面，核对当前约定后再决定是否重提；不要重复使用过时确认 |
| 名额已变化或未能接取 | 以刷新后的状态为准；候补不是报名成功 |

普通任务协作仅支持文字成果，不提供通用附件上传；校园发现图片是单独的图片功能。系统没有站内私聊、真实支付、官方学分接口、志愿签到签退或学校工作人员认证。网页当前以桌面浏览为主，手机布局尚未专项完成。
