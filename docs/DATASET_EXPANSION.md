# 校园活动实验数据集扩充方案

状态：本文件保留原始扩充设计及其验收配额；目前已有部分真实采集。当前覆盖、源绑定和待补项以[数据集审计](dataset_samples/STATUS.md)为准，规划配额不计入已完成数据量。

## 1. 复用什么

复用两种对话流程：组织者说明需求、Agent追问、生成草稿、人工确认；参与者表达偏好、Agent整理、独立确认、推荐与解释。两种流程都覆盖志愿活动和综素活动。

已审核的书信志愿、小满游园是两个活动原型；PART-MATCH-001提供人物条件、匹配判断和生命周期的参考。模板复用业务结构、信息披露方式和验收方法；各活动单独定义事实、未知项和标准答案。

以下三个单位分别统计：

| 单位 | 含义 | 举例 |
|---|---|---|
| 活动场景 | 有独立规则和来源记录的活动底稿 | 固定班次服务、自由到场游园 |
| 受控变体 | 同一底稿只改变一个关键条件 | 可全程参加改为只能参加一小时 |
| 表达变体 | 事实和条件相同，仅改变表述 | 口语需求、推文摘录、碎片消息 |

改名、换日期、同义改写仍属于原场景族。公布场景数、对话数、推荐判断数和真实模型调用数，不混成一个“样本总数”。

## 2. 首批新增四个场景

以下是模拟场景提案，名称仅用于设计；没有对应真实通知，不赋予其真实来源或校方认定。确定底稿时逐项注明来源，模拟规则也需要审核。

| 规划ID | 类型与主题 | 需要明确的新规则 | 主要检验点 |
|---|---|---|---|
| EXP-V01 | 图书整理志愿服务 | 两个独立班次；每人限选一个；各班名额独立 | 保留岗位与班次边界，避免把两个班次都当成必到 |
| EXP-V02 | 校园无障碍路线信息核验 | 分工核验公开路线信息；行前说明；需审核报名 | 准备环节与服务环节区分；要求、产出和时长条件忠实 |
| EXP-A01 | 校园摄影展参观与赏析 | 开放时段内自主参观；提交赏析为模拟完成条件；积分未确定 | 部分时段可参加；区分参加条件与完成条件；未知积分不编造 |
| EXP-A02 | 传统文化专题讲座 | 固定场次；直接报名；模拟签到、签退规则 | 固定出席与自由到场区分；地点相同但时间冲突的反例 |

它们均采用项目已有的活动/志愿、岗位、报名和偏好能力。签到、作品审核、时长及积分只作为公告规则与解释依据；当前项目未实现的核验与认定操作不写成真实工具执行成功。

首批不以换主题作为唯一变化。四个场景分别带来多班次、任务要求、自由到场、固定场次等规则差异。写底稿时检查是否与原型实质重复，重复则降为变体。

## 3. 每个场景固定产出

### 3.1 组织者建档：三个版本

| 版本 | 输入安排 | 观察目标 |
|---|---|---|
| O1 常规 | 首句给出目的，按追问披露其他信息 | 能否问清并生成忠实草稿 |
| O2 信息缺失 | 相同底稿中保留一个明确未知项，如积分或联系人 | 是否保留未知、正确使用待确认或非必填字段 |
| O3 信息修正 | 用户后续更正一个关键值，如日期或某班名额 | 是否替换旧值、维持相关字段一致、重新获得必要确认 |

O2的未知项不得选择系统创建所必需且无法留空的值后仍要求“成功发布”。此时正确终点是待补充草稿。每个版本预先定义允许终点和禁止操作。

### 3.2 参与者推荐：八个条件探针

1. 兴趣、类型、时间、地点均匹配。
2. 兴趣匹配但时间确定冲突。
3. 时间地点匹配但兴趣无关。
4. 只覆盖部分时段：固定出席与自由到场按各自规则判断。
5. 缺少一个必要偏好条件，预先标明需澄清还是可条件推荐。
6. 已报名或已有待审申请，检查重复推荐处理。
7. 关闭提醒，分别检查推荐列表与站内消息。
8. 语义相关但关键词不重合，并保留语义解析就绪状态。

八种是覆盖目标，需按场景具体化，不机械套入不适用条件。同一探针的对照只改变目标变量；其余条件固定，便于定位错误。

每对判断记录三层答案：候选是否展示（应展示、条件展示、排除）、说明中必须披露的限制、是否应产生消息。报名审核通过、最终积分认定不由推荐结果推导。列表、解释和消息分别评分。

从八个探针中选三个进行真实自然语言对话：一个完整匹配、一个明确反例、一个场景关键边界。其余先通过结构化偏好与原生服务重放检查，分别报告。

### 3.3 数量与阶段

首批新增4个活动底稿，对应12条组织者对话、12条参与者对话和32对推荐判断。24条指多轮对话记录，32对是人物—活动判断；两者有重叠，不相加宣称56个独立样本。

先完成4条O1和4条完整匹配参与者对话，共8条冒烟采集；审核通过后再采其余16条。32对判断在采集前冻结。已有样本保留为回归参照，不算本轮新增。

随后可扩展到12个活动底稿的公开开发池：已有2个、首批新增4个、后续再新增6个。后续6个优先补充周期服务、多岗位要求、同主题不同报名规则等空缺，先检查产品支持和独立规则，再决定主题。不同批次结果按底稿与版本汇总，不能把未采集配额算作成果。

## 4. 从底稿到实测的生产流程

1. **建立活动事实表。** 先写目的、对象、时间、地点、岗位/内容、名额、报名方式、完成条件、认定边界与未知项。每项附来源类型和证据位置。
2. **审核业务规则。** 检查日期、开放与截止、班次容量、条件依赖、积分口径是否一致；区分真实材料与模拟补充。
3. **冻结标准答案。** 写出期望字段、需要追问的信息、允许未知项、正确终点、禁止操作和推荐判断。标准答案不从被测程序的输出反推。
4. **组织输入材料。** 根据事实表制作推文式通知、口语首句、按主题披露卡。缺少图片内容时仅标记未提供，不能由“图片”占位符推断具体规则。
5. **静态校验与审核。** 检查结构、时间、来源、信息卡覆盖和变体差异；通过后生成哈希冻结。人工重点检查规则和歧义。
6. **调用真实系统。** 每个对话使用独立实验库、固定业务时钟、原生业务接口；依据Agent实际追问返回卡片，保存完整输入输出与工具轨迹。
7. **分类评估并交付。** 区分自主完成、人工辅助完成、内容失败、基础设施中断；单独保留用户审核结论。模型输出失败也属于有效评测证据，不删除或改写为成功。

可用模型辅助写推文和表达变体；这些是合成输入，不是实际采集对话。自动扮演组织者时仅提供事实表和披露规则，不给它生成成功轨迹的任务，也不让它替被测Agent补完未追问的答案。初期继续人工选卡，待复核自动选卡忠实性后再扩展。

## 5. 配置与工程改造

当前`examples/collect_letter_sample.py`已可按样本目录读取冻结规格；`examples/participant_samples.py`仍固定活动、人物和时间；旧`examples/simulation_dataset.py`含固定表格规模。扩充时保留既有执行器和冻结结果，新增配置驱动入口，逐步复用其中的服务调用与日志逻辑。

建议每个场景采用以下目录，不强制所有场景都是20条事实或五张信息卡：

```text
<scenario_id>/
  scenario.json          # 活动事实、业务时钟、来源、场景族与版本
  organizer_cases.json   # 首句、披露卡、修正规则、允许终点
  participant_cases.json# 人物条件、确认方式、场景状态
  gold.json              # 隔离保存的标准答案与评分依据
  REVIEW.md              # 可读底稿与审核重点
  validation.json        # 实际静态校验结果
  manifest.json          # 冻结清单与哈希
```

采集轨迹仍写入独立`.runtime/evals/dataset/`目录。记录模板版本、来源分组、随机种子、模型与参数、提示/工具版本、重试策略、语义缓存状态和是否辅助；新运行不覆盖旧运行。输入呈现器不可将gold、未披露卡片或评分规则传给被测Agent。

实现顺序：配置契约与校验器 → 单场景配置重放 → 与现有种子对照复现 → 四个新底稿 → 8条冒烟采集 → 完整首批。规则判定器独立于项目匹配器；有歧义的标签交由人工审核，不能调用同一匹配实现生成金标准。

## 6. 评估、成本与数据划分

- **组织者：** 事实忠实、必要追问、修正一致性、最终保存状态与确认边界分别报告；原有评分项需随新场景重新核对适用性，保留关键错误否决项。
- **参与者：** 偏好忠实、确认授权、候选展示precision/recall、条件披露、消息触达分别报告。结构化矩阵结果和自然语言对话结果分别统计。
- **运行：** 记录完成率、时延和可取得的token用量；模型/解析超时、回退模式独立报告，提前规定重试上限，保留首次结果。token或价格未知时不估造费用。
- **流程：** 去重、满额、取消、截止等生命周期按业务机制选代表场景复测；没有必要把相同机制复制到每场活动来增加条数。

已接受样本仍保留三对漏推荐及解析回退。用户接受样本不等于实现全部通过。新数据继续按独立规则标注；若要用它比较纯语义匹配，需先取得语义解析就绪的可比快照，否则报告真实混合模式，或单列基础设施结果。

当前全部已公开种子及其衍生变体归入开发/演示集合。同一来源、同一活动底稿、同一人物设定衍生的对话必须在同一集合，不能随机按消息行切分。

正式未见评测另外建立独立来源和规则组合的场景族，冻结后不参与提示与算法调整；修复已暴露问题后用独立场景验证迁移。若暂时只有两个来源原型，就把数据称为模拟开发与回归集，不宣称代表真实校园活动分布。受控边界样本与后续自然抽样样本分别汇报。

## 7. 当前执行顺序

先按[覆盖目标](dataset_samples/coverage_targets.json)补齐首批四场的O1/O2/O3与参与者正例、反例、边界对话；解决审计发现的叙述/结构化偏好不一致和缺少静态检查项的问题。已采集但缺少当前规格绑定的轨迹保留为历史证据，新增或复采记录必须绑定冻结源，并保存阶段检查。完成首批原定配额后再扩展后续场景池。

每次扩增都更新审计索引。已观察到完成、当前规格可追溯完成、模型内容通过和用户审核通过四种状态分别记录。
