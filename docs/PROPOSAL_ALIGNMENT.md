# 引航岛活动筹备与参与助手

本版以《申报书 (1)(1).docx》为新增功能依据。核心流程是组织者描述构想、引航员澄清并整理活动方案、负责人确认发布、参与者授权偏好、后台匹配并提醒、参与者自主报名、引航员查询实际状态。普通任务和校园发现继续作为扩展场景。

## 使用方式

登录后进入“引航员”。选择“筹备志愿活动”或“筹备综素活动”，说明活动目标。模型使用独立活动草稿工具收集信息，不再要求组织者全部从空白表单开始填写。未明确的条件继续追问；岗位划分和执行安排可作为建议保存。未确认建议单独显示，只有正式字段才进入发布数据。

方案卡片可直接编辑活动内容、报名窗口、岗位、人数、时间、认定条件等字段。保存表单修改后，服务端显示待补全项。完整方案须由本人点击“核对并确认发布”。确认重新检查版本、账号、时段与业务规则，在同一事务内创建活动并更新草稿；重复确认同一版本不重复创建。已发布方案不能作为新的活动再次修改，需开始新对话。

参与者可以说“我会摄影，对环保活动感兴趣，本周六下午有空，请关注新机会”。模型整理偏好草稿，用户核对后保存。技能、兴趣、地点、一次性空闲、每周空闲、不可参与时段、偏好有效期和内容类型分别存储。每周按北京时间计算，周一为0；一次性时段不会自动变成每周重复。技能为用户自述。未明确要求提醒时默认关闭，用户可随时修改设置。

后台每5秒扫描当前业务状态与已保存偏好，生成或更新机会记录。无须打开聊天页，应用服务保持运行即可持续匹配。机会来自志愿岗位、综素活动，以及用户选择的普通互助任务。时间冲突、已过截止、取消、满额、本人发布、本人已有有效报名或申请的机会排除。兴趣、技能描述与地点采用可解释的文本匹配排序；未知的资格条件明确列为待核对条件，不推断用户一定符合。普通任务缺少确定协作时段时单列待协商提示。

开启提醒后，新机会写入站内消息。推荐与通知在同一事务内提交，按用户、内容类型、活动和岗位去重，重启或重复扫描不重复提醒。“不再推荐此机会”会保留用户选择。取消、过期、名额或报名状态改变后，后台使不再适用的推荐失效。站内消息保留已发生提醒，点击后查看当前业务详情。此版未接入站外推送。

报名、审核、参与登记、志愿小时确认仍由用户或负责人在相应页面操作，Agent 使用工具查询真实记录，不代做业务决定。活动方确认与学校正式认定保持原有区分。

## 调用轨迹

对话下方显示实时调用轨迹，运行记录中可重新打开历史轨迹。支持时长和轮次视图、工具搜索、选择节点查看摘要。紫色为模型响应，橙色为工具，失败显示红色；执行中、完成、失败、中止使用真实运行状态。工具节点按 call_id 对应开始与结束事件，显示时间戳、轮次、耗时和输入字段或结果数量摘要。

保留原有 SSE 重连和取消机制。轨迹不持久化模型内部推理、原始工具参数或原始工具结果，用户只能读取自己的运行记录。取消或失败不提交本轮暂存的活动方案、偏好草稿或对话。

## 工程接口

| 接口 | 用途 |
| --- | --- |
| GET /api/guide/preferences | 本人已确认偏好与版本 |
| PUT /api/guide/preferences | 用户在表单确认保存偏好，版本冲突返回409 |
| GET /api/guide/assistance/{conversation_id} | 本人活动方案与待核对偏好 |
| PUT /api/guide/assistance/{conversation_id}/plan | 审阅页面编辑方案 |
| POST /api/guide/assistance/{conversation_id}/publish | 用户确认发布当前版本 |
| POST /api/guide/assistance/{conversation_id}/cancel | 取消未发布方案 |
| POST /api/guide/assistance/{conversation_id}/preferences | 用户确认授权偏好草稿 |
| GET /api/guide/recommendations | 本人推荐与匹配时间 |
| POST /api/guide/recommendations/refresh | 手动重新匹配 |
| POST /api/guide/recommendations/{id}/dismiss | 停止推荐指定机会 |

数据库新增3张表：guide_assistance、participation_preferences、opportunity_recommendations，复用原有账号、对话、活动、岗位、报名与站内消息。活动发布服务支持调用方事务，草稿发布不会绕过现有业务校验。后台匹配使用应用配置的业务时钟，兼容独立模拟环境。当前部署仍为单进程、单实例原型。

## 验收与复现

自动测试：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_assistance.py -v
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
npm.cmd --prefix web run build
npm.cmd --prefix web run test:accounts
npm.cmd --prefix web run test:changes
```

完整链路验收默认使用临时数据库和脚本模型，测试真实服务、草稿、偏好、发布、推荐、通知、报名与状态查询：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m examples.proposal_check
```

真实模型验收读取本机模型配置，向远端仅发送合成活动与演示账号的上下文，不读取正式业务数据：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m examples.proposal_check --real-model
```

报告分别写入 .runtime/evals/proposal-offline-latest.json 和 proposal-real-latest.json。可使用 --directory 指定独立目录保留验收库，方便浏览器继续检查；再次验收应指定新目录，避免既有偏好或活动影响空库断言。

需求补全评价关注关键字段是否完整、是否忠实于用户原话、缺失条件是否追问和是否错误填入；推荐评价关注硬时间冲突、实际可参与状态、解释依据、提醒去重与用户接受情况；查询评价比较模型所用工具与数据库实际报名状态。报告记录流程成功率和对话耗时。模拟及真实模型检查不能替代实际用户试用，组织沟通成本和参与便利性的改进幅度需在小范围试用中测量，未填写虚构效果数据。
