# 活动规划与语义推荐改进

本轮完善发布前的志愿／综素草稿与真实机会匹配。普通任务、校园发现和既有业务入口继续保留，正式发布、报名、审核和小时核验仍由有权限的用户执行。

## 组织者如何使用

1. 在引航员中描述活动构想，明确的信息整理到草稿，未知条件继续追问。模型推测的岗位、人数、设备安排属于建议。
2. 表单中填写可选的“计划招募志愿者总人数”。这表示招募志愿者人数，不表示活动观众人数；未设置时不做总人数一致性推断。
3. “方案检查”展示后端必填、日期顺序、岗位越界、服务分钟、总人数矛盾等阻塞问题。
4. 点击“让引航员评估方案”。模型读取当前草稿，提交有依据的建议、待确认条件和复核事项；该专用入口只开放 `get_assistance` 与 `review_activity_plan` 两个工具。
5. 展开建议依据和拟修改字段；逐条拒绝、采纳或编辑后采纳。采纳只改草稿，随后重新校验。修改草稿会使旧建议失效，跨账号及旧版本操作由后端拒绝。
6. 每次对话或表单修改记录实际前后差异。岗位使用内部稳定标识，支持改名、增删和排序。活动时段变化不会自动平移岗位。
7. 用户修复阻塞问题并核对内容后，单独确认发布。发布时转换到现有业务输入，不修改正式岗位接口。

AI 建议与后端检查分别展示；未采纳建议不能阻止发布。建议的业务合理性仍需要组织者核对，证据校验保证引用存在于当前草稿，不能替代对整段建议含义的审阅。

## 参与者如何使用

保存参与偏好后，后台对技能、兴趣与岗位文本提取受控标签。标签原文证据可在偏好区域查看；错误标签可停用和恢复，原始自述不会被覆盖。若需要改成另一项技能，编辑原始偏好后重新归纳。

首版标签包括摄影、视频拍摄、视频剪辑、文案、设计、讲解、引导、活动支持、相机，以及环保、公益、教育、文化、科普。摄影、视频拍摄与剪辑分别匹配；拍过宣传片不意味着会摄影或拥有相机。

匹配依次检查真实业务状态、截止、名额、重复报名与空闲时间，再按技能、兴趣、地点、已确认时间排序，权重为 55/30/10/5。技能与兴趣按岗位相关标签覆盖比例计分，至少命中技能或兴趣之一。地点一致不能单独生成个性化推荐；排序分不作为成功概率展示。

必需条件与明确否定冲突时排除。设备、资格和熟练程度未知时列为待核对，保留岗位原文要求。推荐解释来自持久化的 `reasons`、`checks`、`semantic_evidence`，不让模型自行补充资格。

## 异步解析与失败处理

- 后台语义任务与五秒推荐扫描分离；扫描只使用数据库，不调用模型。
- 缓存键绑定来源类别与标识、原文摘要、标签体系版本、解析提示摘要、模型及服务端点配置。原文变化后立即无法命中旧缓存，旧排队任务作废。
- 每份有效的新内容正常只解析一次。失败不写成功缓存，最多三次尝试并退避；期间明确显示关键词匹配。服务重启恢复未完成任务。
- 保存偏好和发布不等待模型。模型调用不持有数据库写事务；解析只向模型发送需理解的文本，不发送账号标识、联系方式或可用时间表。
- 推荐和站内消息沿用持久去重、“不再推荐”和实时状态重新校验。
- 历史草稿按读取补齐元数据；历史业务原文不重写，语义缓存按需生成。

## 接口与代码

| 接口 | 用途 |
|---|---|
| `GET /api/guide/assistance/{cid}` | 草稿、检查、最新差异、影响与评估 |
| `PUT /api/guide/assistance/{cid}/plan` | 版本化表单编辑、岗位标识及总人数 |
| `POST /api/guide/assistance/{cid}/review` | 异步只评估，返回运行 ID，复用 SSE 与取消 |
| `POST /api/guide/assistance/{cid}/proposals/{id}` | 版本化采纳／拒绝及用户编辑后的建议 |
| `GET /api/guide/assistance/{cid}/revisions` | 本人草稿最近 30 次字段修改记录 |
| `GET /api/guide/semantics/preferences` | 当前偏好标签、证据、缓存状态和版本 |
| `POST /api/guide/semantics/preferences/correction` | 按偏好版本停用／恢复标签 |

确定性规划与差异在 `campus/planning.py`，建议决定在 `campus/planning_actions.py`；语义任务在 `campus/semantics.py`，业务筛选与排序在 `campus/matching.py`。独立表保存语义任务、缓存和草稿版本历史。

## 可复现验证

以下命令在项目根目录执行；真实模型命令使用现有 `.env`，会发生模型调用。评测和演示默认使用 `.runtime/evals/agent-improvements/` 下的隔离数据库。每次全新演示生成独立数据库，路径保存在结果 JSON 的 `database_path` 中；`--resume` 仅恢复尚未发布的失败草稿。

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests
npm.cmd --prefix web run build
npm.cmd --prefix web run test:planning
npm.cmd --prefix web run test:trace
.venv/Scripts/python.exe -m examples.improvement_eval --real-model --suite all --repeats 3 --workers 2
.venv/Scripts/python.exe -m examples.improvement_demo --real-model
```

规划语料含 20 个主流程自然语言案例及 2 个取消／跨账号边界案例，覆盖缺失条件、分工、人数、改时段、岗位改名／排序／增删、清除字段、建议采纳／拒绝／过期及未知设备。真实运行逐条保存，包含错误和耗时；不会把失败替换成成功。

语义语料为 30 组明确参考标签与 13 个岗位，另验证空闲冲突、不可参与、名额、截止、设备否定、相近技能和未知器材。模型只看到来源文本，看不到参考答案。参考答案随代码提供供人工复核，并非外部标注员或用户研究；小型构造集上的提升不能直接推断为真实校园用户效果。对照算法在 `campus/keyword_baseline.py` 冻结，保持改进前关键词权重和判断。

同场演示记录“模糊构想 → 岗位建议 → 采纳 → 提前结束并显示影响 → 人工修正岗位 → 独立确认发布 → 宣传片经历匹配视频岗 → 相机未知提示 → 去重提醒”。演示中的表单操作代表显式用户确认，分别统计模型调用和人工表单提交，不伪称真实受试者操作次数。

单元测试通过 `tests/app_factory.py` 默认关闭远程语义工作线程，避免例行回归意外调用真实模型；生产默认启用。实际验收数据与失败说明见[本轮验收记录](AGENT_IMPROVEMENTS_ACCEPTANCE.md)。
